# ADR 0005:可配置的 hook 静默与按需错误信封

- 状态:已接受,取代 ADR 0004 中仅向用户通知的错误报告策略

## 背景

Source hooks 由用户显式配置,失败原因应帮助模型诊断环境问题。初始化失败与实际命令执行是两个独立结果,直接混在命令输出中容易误导模型。正常路径不需要模型了解环境准备协议。

## 决策

- 每条 hook 支持布尔配置 `quiet`,默认 `false`。默认模式每次生成失败都向模型报告诊断,不另行通知失败或恢复;静默模式保留首次失败和恢复的用户通知,不向模型投递错误。
- 失败继续跳过该 hook 的环境更新,实际命令仍会执行。命令结果的成功和失败由实际执行决定。取消不作为 hook 故障报告。
- 捕获有限长度的 stderr,成功时丢弃,失败时与退出码、启动失败、超时或输出超限原因一起报告。
- 每条诊断包进 `<pi-bash-jobs action="source-hook" hook="…" outcome="failed">` 信封。stderr 使用内层 `<command-output stream="stderr">`。配置错误使用 `action="config"`,正文包含配置文件与条目位置。
- 属性值转义,正文中信封及内层标签的开闭前缀转义。每个信封最多 8192 字符,预算包含标签与说明,截断后保留闭标签。
- 不增加系统提示。每个 session 首次投递非静默错误时,在信封内说明 hook 环境更新已跳过、实际命令继续运行,接下来的块是 hook 错误输出。首次错误是配置错误时使用对应的配置说明。后续信封只保留归因和诊断。静默错误不消耗首次说明机会。
- 诊断独立于 shell stdout 和输出截断,不参与 shell 脚本执行。生成错误发生在转后台之后时,诊断保留在 job 上,经后续 wait 或 kill 取回。
- 配置诊断继续通知用户,同时在下一次 bash 调用时向模型报告一次;重新加载配置后可以再次报告。

## 理由

专属信封和按需解释沿用 pi-cues 的边界原则,同时避免在每次会话启动时加入与当前任务无关的提示。默认可见让模型获得环境故障依据,逐 hook 静默保留用户对高频、预期失败的控制。独立诊断块避免大量命令输出截掉信封边界,也避免让 hook 错误改变已执行命令的成功状态。
