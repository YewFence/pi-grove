# ADR 0004:通过全局 TOML 配置通用 source hooks 刷新 bash 环境

- 状态:已接受
- 日期:2026-10-19

## 背景

pi 会话启动后,bash 子进程继承宿主进程的环境。环境管理配置变化后,后续工具调用需要重新生成初始化代码。不同用户使用 mise、direnv 或自定义脚本,扩展需要通用接口,让用户通过配置启用自己的刷新方式。

## 决策

- 读取 `<agent-dir>/extensions/pi-bash-jobs/config.toml`,其中 `<agent-dir>` 尊重 `PI_CODING_AGENT_DIR`,默认 `~/.pi/agent`。只支持全局配置,不读取项目配置。
- 配置使用 `version = 1` 和有序的 `[[source_hooks]]` 数组。每条包含 `name`、非空 `command` 参数数组和可选的 `timeout_ms`。
- 会话启动时加载配置,`/reload` 后重新读取。没有配置文件时不执行任何 hook。
- 每次 bash 调用前,在本次工作目录中直接启动 hook 命令,继承 bash 的初始环境。命令无需 shell 解析,stdout 是待执行的 bash 代码。
- hook 按声明顺序生成代码,随后在实际 bash 之前按顺序应用。生成进程彼此不继承前一条生成的环境修改。
- 每条 hook 默认超时 3000ms,stdout 限制为 1 MiB。命令缺失、非零退出、超时或输出超限时丢弃该条全部输出,继续其他 hook 和实际命令。失败和恢复状态变化时通知用户,下一次调用继续重试。
- 取消调用或关闭会话时终止命令 hook 及其子进程,阻止后续 hook 和实际 bash 启动。
- 配置解析失败时报告文件位置;无效条目单独报告并跳过。通知不进入模型上下文。
- 保留 TypeScript `SourceHook` 接口作为编程入口,在配置 hook 之后执行。移除 mise 专用接口、默认启用逻辑和开关;mise 仅作为文档示例。

## 理由

stdout source 协议可以直接表达 `export`、`unset` 及其他 bash 初始化操作,无需扩展解析 shell 或合并环境快照。命令数组保留参数边界,用户需要复杂初始化时可调用自己的脚本。执行、限时、取消、输出限制和状态通知由统一实现负责,普通用户只需声明命令。

使用现有 TOML 库解析格式,由 bash-jobs 自己声明依赖。参考 cues 的配置加载和诊断模式,不跨包导入源码,保持包独立安装。

## 已知限制

- 所有生成进程基于同一个初始环境。有依赖的初始化步骤需要放在一个脚本中。
- 生成代码在 `set -e` 下执行。语法错误或执行失败会阻止实际命令,并通过 bash 结果显式返回。
- TypeScript 编程 hook 自行管理资源并响应取消信号,配置命令的资源管理由扩展提供。
- 第一版不提供项目配置、文件监听或 hook 插件发现。配置文件修改后需 `/reload`,hook 命令本身每次调用都会重新执行。
