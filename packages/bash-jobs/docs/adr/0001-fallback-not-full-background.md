# ADR 0001:兜底而非正式后台,不改模型习惯

- 状态:已接受
- 日期:2026-09-28

## 背景

pi 原生 `bash` 的 `timeout` 到点直接 `SIGKILL` 整个进程组,不设 timeout 则无限阻塞。这让模型陷入一个具体的坏循环:`timeout` 写短了 → 命令还没跑完就被杀 → 模型不知道是超时还是真失败 → 重试时把 `timeout` 写得更短,又被杀。同步等待卡住的情况也类似,模型没有体面的让出通道。

同时,pi 官方没有一个可靠的 wait 原语:模型要等一个已知会跑一段时间的命令,只能靠估算 `sleep` 之类的间隔去轮询,而不是「我等它结束,最多等 N 秒」。

这个项目要解决的是上面这两件事,定位的取舍发生在奠基那天。

## 决策

把项目定位成**兜底**层,不是正式的后台任务方案。具体含义:

- **复用 pi 内置 bash 的执行层**,只把 `timeout` 语义从「到点杀」改成「到点让出」——到点返回已有输出,进程转入后台继续跑,不杀。未设 timeout 时,连续静默一段时间也让出,防无限阻塞。
- **不改变模型习惯**:`bash` 的参数仍是 `command` 和 `timeout`,不引入 `background: true` 之类的新概念。模型要刻意把命令放到后台,直接 `nohup` 就够了,这个插件不接管那种意图。
- **结果交付走 pull 模型**:模型用 `bash_wait` 拉取后续输出,配指数退避;**不**在 job 完成时往会话注入消息、**不**唤醒 agent。模型不主动查,完成就静默等着。
- **代价**:用同名工具替换内置 `bash`,因此与其他替换 `bash` 的扩展互斥。

## 理由

**「不改模型习惯」是这个生态位唯一没人占的空隙。** 奠基当天(2026-09-28)的调查覆盖了 `gh search repos`、awesome-pi 的 Background Tasks 分区、各候选仓库的 README,结论是正式 background-bash 路线已有成熟插件,但没有人做这种轻量兜底。最接近的同类是 `sshkeda/pi-background-bash`,它走的是处处相反的路线:`background: true` 主动放后台、固定 30 秒转后台、完成时注入 context 并唤醒 agent、v1 起用自有 PBB runner 接管执行。完整对比沉淀在 `ecosystem.md`。

选 pull 而非 push,是因为这个插件解决的是「让出与续命」,不是「完成即交付」。`bash_wait` 兼任了上面提到的 wait 原语:模型要等一个慢命令,给它一个 `timeout` 然后用 `bash_wait` 续上就行,不需要高频轮询拼时长。一旦改成完成时唤醒 agent,就跨进了正式后台方案的边界,和 pi-background-bash 的定位重叠,反而失去存在的理由。

复用内置执行层是为了「够轻」:执行、截断、临时文件、渲染全部复用,快路径与内置完全一致,其他扩展挂在 `bash` 上的 `tool_call` / `tool_result` 钩子照常生效。这是兜底层应有的边界——只改语义,不换地基。

## 被否掉的备选

- **正式 background-bash(`background: true` + 完成唤醒)**:`pi-background-bash` 已经做了,且这正是本项目刻意要避开的路线——它改变了模型习惯(新参数)、改变了结果交付模型(push)、换了执行层。照搬就等于多造一个 pi-background-bash。
- **完成时注入 context 并唤醒 agent**:违背 pull 模型,也让这个插件跨进正式后台方案的边界。需求方确认:不需要主动通知,模型用 `bash_wait` 取回即可。
- **回到原生「timeout 到点杀」**:直接消灭项目的核心价值——转后台续命的命令会变成尸体。

## 后果

- 正面:`timeout` 从死刑改成检查点,模型不再陷入「写短→被杀→写更短」的循环;`bash_wait` 提供了 pi 官方缺失的可靠 wait 原语;工具表面积只比内置多两个工具(`bash_wait`、`bash_kill`),提示词负担极小。
- 负面/残留:与其他替换 `bash` 的扩展互斥(`pi-codex-conversion` Structured、`pi-background-bash`);job 完成不主动通知,模型不查就不知道——这是 pull 模型的代价,需求方已接受。
- 演化:这个定位在 2026-10-13 的 ADR 0003 里被进一步收紧——`timeout` 不仅要让出,还要足额等待,静默不提前转后台。本地遥测数据(441 次 yield 中 226 个续命后成功交付)反过来坐实了「让出而非杀掉」的价值。
